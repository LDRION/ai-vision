# AI-компания — оркестрация

Один вход (запрос человека или сигнал системы) → оркестратор обсуждает подход,
планирует, распределяет между агентами-специалистами по отделам, те исполняют
реальными инструментами (видят экран, слышат, пишут, рисуют, монтируют,
публикуют руками), сводят отчёты. Работает в потоке, параллелит независимое,
необратимое держит на подтверждении человека, учится на удачных прогонах.

## Как это запустить

```powershell
python -m aivision.orchestrate_cli --agents                  показать команду
python -m aivision.orchestrate_cli "запрос"                  план (без мыши)
python -m aivision.orchestrate_cli "запрос" --run [--execute] исполнить
python -m aivision.pulse [--loop 300] [--run [--execute]]    24/7-пульс
```
Или в лаунчере: кнопка **🏢 Команда** — оргсхема, запрос, план, пульс, подтверждения,
журнал, задачи; клик по агенту открывает редактор, «Знания» — общий контекст.

## Агенты (определения — в git)

Каждый агент — markdown-манифест `agents/<имя>.md`: YAML-заголовок (имя, описание,
`capabilities`, `tools`, `app`, `department`, `reports_to`) + тело = системная роль.
Новый сотрудник = новый .md (или кнопка «+ Агент» в окне). Лид отдела — агент с
инструментом `orchestrate`.

Инструменты (`tools`) → как агент реально действует:

| tool | что делает | движок |
|---|---|---|
| `scenario` | видит экран, водит мышью и клавиатурой (открыть приложение, загрузить файл, опубликовать) | этот проект |
| `groq` | распознаёт речь, делает выжимку | Groq Whisper/чат (из unusual-ai) |
| `text` | пишет тексты и ПРОМТЫ для других агентов | Siberi |
| `image` | генерирует картинки (шапки, обложки) | Stable Diffusion WebUI |
| `video` | монтирует ролик из материала (биты, титры, рендер) | dumaem edit |
| `ssh` | работает на хостинге: логи, статус, деплой проектов (Откликс, Siberi) | системный ssh |
| `orchestrate` | руководит отделом, делегирует | — |

## Поток работы

1. **Стратегия** (`strategize`) — короткий подход с учётом знаний команды, в журнал решений.
2. **Память планов** (`plan_memory`) — похожую задачу уже решали? берём готовый план, без Siberi.
3. **План** (`plan`) — разбивка на подзадачи с агентами и зависимостями `depends_on`.
   Независимые шаги НЕ связываются → идут параллельно.
4. **Исполнение** (`dispatch`) — независимые шаги параллельно (до `max_parallel`, по умолчанию 3);
   зависимый ждёт результат предка и получает его как контекст. Сбой → повтор (`retries`),
   не вышло → эскалация лиду/человеку. Необратимое/денежное → подтверждение человека.
5. **Отчёты и журнал** — каждый шаг пишет отчёт и строку в журнал; итог сводится на родителе.

## Рабочее пространство (операции — вне git, `company/`)

- `inbox/` — входящие задачи (пульс кладёт сюда найденные просадки).
- `tasks/<id>/` — задача: `task.json`, `log.md`, `artifacts/`.
- `reports/<id>.md` — отчёты. `outbox/` — готовое для человека.
- `knowledge/` — общий контекст (бренд, тон, стратегия) — питает план и роли.
- `approvals/` — что ждёт подтверждения человека.
- `state/` — `journal.md`, `plans/` (память планов), `overrides.json` (правки промтов на лету).

Определения (`agents/`) версионируются в git; операции (`company/`) — рантайм, личные, вне git.

## Реестр ссылок и доступы (всё по полочкам)

- **Реестр** (`resources/*.md`, в git, БЕЗ секретов) — ссылки и данные проектов: сайты,
  Telegram-каналы и боты, VK/YouTube, панели метрик, кабинеты. Подмешивается в план, чтобы
  агент знал, куда идти. Токены/пароли сюда не кладём — они в `company/` (вне git) и `.env`.
- **Доступ** (`governance.py`) — у каждого реестра в заголовке `owners` (какие роли могут
  править) и `approval` (нужна ли виза). Оркестратор правит всё; остальные — только свои
  документы. Редактор — кнопка «Ссылки» в окне «Команда».
- **Виза оркестратора** — серьёзные действия нижних агентов (создать бота, выдать права,
  привязать аккаунт, настроить платежи/канал/домен) `dispatch` не делает молча: они уходят
  на подтверждение человека (`governance.needs_signoff`). Это и есть «разбор действий снизу».

## Проекты, хостинг и ритм

- **Проекты** (`projects.py`, `company/projects.json`) — что ведёт «единый мозг»: `ai-vision`
  (локально), `Откликс` и `siberi.online` (на хостинге по SSH). Пульс оценивает по всем проектам.
- **Хостинг по SSH** (`remote.py`) — хост задаёшь ты (окно «Проекты» или `company/state/hosts.json`,
  либо env `AV_SSH_HOST`); ничего не хардкодится. Чтение (логи, статус) выполняется; изменяющие
  команды (деплой, `rm`, `git push`, рестарт) распознаются и уходят на подтверждение человека.
  Команда берётся из задачи в `обратных кавычках`.
- **Ритм «без фанатизма»** (`policy.py`) — дневные лимиты: максимум 1 публикация и 1 ролик в сутки.
  Задачи-публикации/видео сверх лимита пропускаются. Счётчик — в окне «Проекты».

## Принципы

- Необратимое, денежное и изменяющее сервер — только с подтверждением человека.
- Каждый агент знает: где его роль, куда отчитываться, кому передаёт задачу («карта места»).
- Оркестратор сам выбирает агентов; GUI-шаги уходят тем, кто управляет экраном.
- Самообучение: удачные планы и сценарные рецепты запоминаются и переиспользуются.
- Без фанатизма: единый ритм публикаций, не спамим соцсети.
