# AI-компания — роадмап

Цель: один вход (запрос человека или сигнал системы) → оркестратор планирует,
распределяет между агентами-специалистами по отделам, те исполняют реальными
инструментами, сводят отчёты. Работает в потоке 24/7, сам замечает просадки.

Опора — то, что уже сделано в этом проекте: движок **зрения** (управление экраном),
**слух** (Groq в unusual-ai), **рецепты** (самообучение), и готовые проекты на этом компьютере.

## Сделано
- Движок управления экраном: зрение (UIA+OCR), действия (клик/ввод/drag/stroke/клавиши),
  человеческое движение, самокоррекция, подсказки, обучение на опыте, рецепты (быстрый путь).
- Лаунчер: вкладки, сценарии, очередь, запись/таймлайн, exe + dev-автоперезапуск.
- Оркестрация: агенты-манифесты, отделы и иерархия, маршрутизация, план, диспетчер
  с передачей результатов, создание агентов промтом, смена системных промтов на лету,
  рабочее пространство (задачи/отчёты/карта места), сквозной `orchestrate`.
- Параллельность (до `max_parallel`), ретраи и эскалация, память планов, стратегия,
  автопочинка плана, пульс 24/7, подтверждение человеком рискованных шагов.
- Хостинг по SSH (Откликс, siberi.online), реестр проектов, дневной ритм «без фанатизма»,
  роли отделов: маркетинг (SMM/SEO/GEO), аналитика (Метрика/Analytics), юрист, DevOps, документалист.

## Дорога (по приоритету)
1. **Боевое исполнение инструментов.** Адаптеры `(task, context) → {status, answer}`:
   `scenario` — готов (движок зрения); `groq` — слух из unusual-ai; `image` —
   stable-diffusion-webui; `video` — dumaem/AIvideomusic; `text` — генерация промтов/текстов.
   Каждый агент знает свой инструмент и не выходит за его рамки.
2. **UI оркестрации.** Вкладка: запрос → план по агентам → «Выполнить» → живой просмотр
   (переиспользуем «Схему»). Редактор агентов и оргсхемы прямо в окне.
3. **Планировщик 24/7.** Фоновая оценка просадок (воронки, контент, соцсети, обратная связь):
   сам ставит задачи в `company/inbox`, оркестратор их разбирает. Расписания и приоритеты.
4. **Память и стратегия.** Общая база знаний `company/knowledge`, журнал решений, обсуждение
   стратегии между лид-агентами перед многошаговыми процессами.
5. **Надёжность.** Подтверждение необратимых и финансовых действий человеком, журнал всего,
   лимиты, откат. Безопасность данных (ключи, логины) по правилам проекта.
6. **Единый мозг по проектам.** Оркестратор влияет на хостинг-проекты (Откликс, siberi.online)
   по SSH, снимает метрики (Яндекс Метрика, Google Analytics) экранным агентом, ищет слабые
   места и ставит задачи — тут и «там». Следующий шаг: самоулучшение агентов (правка их
   промтов при повторных сбоях) и живой просмотр сценарных шагов во время оркестрации.

## Принципы
- Определения (кто есть кто) — в git (`agents/`); операции (поток работы) — вне git (`company/`).
- Необратимое и денежное — только с подтверждением человека.
- Каждый агент всегда знает: где его роль, куда отчитываться, кому передаёт задачу.
